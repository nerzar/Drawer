# Тесты Drawer

Тесты Drawer могут управлять настоящими окнами, мышью, фокусом и запущенными приложениями. Поэтому **основное место для runtime-тестов — подготовленная Windows VM**.

На основной Windows владельца любые тесты Drawer, которые запускают `drawer.ahk`, двигают окна, меняют фокус или вмешиваются в рабочий стол, запускать **только по прямому запросу владельца**.

Если VM временно не работает, это не разрешение автоматически перенести прогон на хост. Сначала сообщить о проблеме.

## Основной запуск в VM

```powershell
powershell -ExecutionPolicy Bypass -File test\run.ps1
powershell -ExecutionPolicy Bypass -File test\run.ps1 -Suites all
powershell -ExecutionPolicy Bypass -File test\run.ps1 -Only geom,kromka
```

Стенд рассчитан прежде всего на изолированную Windows с двумя мониторами. Конкретные сценарии и требования лучше сверять по самому `run.ps1` и драйверам: старые названия наборов и исторические результаты не являются продуктовыми требованиями.

## Что проверять автоматически

Автотест имеет смысл, если быстро ловит конкретную техническую ошибку: геометрию, загрузку конфига, сохранение Settings, lifecycle, отсутствие окна на соседнем экране и другие измеримые свойства.

Не использовать зелёный тест как доказательство правильного UX. Для поведения окон, кромок, фокуса, Alt+Tab, панели задач, анимации и нескольких мониторов при необходимости нужна короткая ручная проверка владельца.

Не строить новый большой тестовый контур вокруг уже воспроизведённого пользователем бага, если быстрее сделать минимальное исправление и проверить его руками.

## Узкие проверки

Некоторые проверки не управляют рабочим столом и работают только с временными файлами или frontend-кодом. Даже их на машине владельца не запускать автоматически: правило хоста остаётся простым — **только по запросу**. В VM их можно использовать свободно, если это полезно для задачи.

## Важно

- Production `config.ini` не должен использоваться как тестовый файл.
- После runtime-прогона не должны оставаться окна за пределами экранов и лишние процессы Drawer.
- Не считать тест пройденным только потому, что его код выглядит логично; сам тест тоже может быть ошибочным.
- Актуальное продуктовое поведение определяет `docs/PRODUCT_SPEC.md`, а не старые тесты или старые отчёты.
