# Стенд

Тесты Drawer управляют настоящими окнами, мышью и фокусом: другого
способа проверить программу, которая только этим и занимается, нет.
Значит прогон **захватывает рабочий стол целиком** — работать за машиной
во время него нельзя, и не из вежливости: физическая мышь перебивает
`MouseMove` драйвера, наведение на кромку не воспроизводится, а
`WinActivate` промахивается и слот привязывается не к тому окну. Ровно
это уже дважды давало ложные провалы.

Поэтому стенд переносимый и без единого абсолютного пути: место для него
— изолированная Windows-VM.

## Запуск

```powershell
powershell -ExecutionPolicy Bypass -File test\run.ps1                 # безопасные наборы
powershell -ExecutionPolicy Bypass -File test\run.ps1 -Suites all     # ещё и настоящие приложения
powershell -ExecutionPolicy Bypass -File test\run.ps1 -Only geom,kromka
powershell -ExecutionPolicy Bypass -File test\run.ps1 -Exe dist\Drawer-v0.1.2\Drawer.exe
```

Код возврата 0 — всё зелено. Логи и собранные для прогона копии
исходника остаются в `%TEMP%\drawer-test\<набор>\`.

`run.ps1` сам находит AutoHotkey v2, прогоняет `/validate`, проверяет
раскладку мониторов, гасит чужой экземпляр ящика, поднимает `mspaint`
для постоянного слота, а в конце ищет окна, оставшиеся за пределами
экранов.

## Что требуется от машины

| | |
|---|---|
| ОС | Windows 10/11 |
| AutoHotkey | v2, интерпретатор (`winget install AutoHotkey.AutoHotkey`) |
| мониторов | **ровно два, второй слева от первого**, оба не меньше 800×600 |
| для набора `apps` | установленные VS Code, Telegram, Chrome и открытое окно Chrome |

Раскладка не косметика. От того, что монитор 2 стоит слева, зависит,
какие края внутренние: `M1/left` и `M2/right` смотрят на соседа, и
именно на них проверяется главный инвариант — выдвинутое окно не
появляется на чужом экране. На другой раскладке проверки не падают, а
начинают проверять не то, что написано в их названиях. `run.ps1`
останавливается на такой машине; `-Force` обходит запрет.

Масштаб DPI проверялся только 100 %.

## Наборы

`safe` — работают на синтетических окнах, которые драйвер создаёт сам.
Ничего постороннего не трогают, кроме `mspaint` как постоянного слота.

| набор | что меряет |
|---|---|
| `geom` | положение окна для каждого сочетания монитор × край |
| `behav` | привязка, hideOnBlur, activateOnShow, Alt+Tab, быстрые нажатия, очистка, выход |
| `invar` | окно ни одним кадром не появляется на соседнем мониторе |
| `quiet` | уведомлений ровно столько, сколько задумано |
| `kromka` | кромки: появление, рост, номер слота, щелчок, стопка, все края и мониторы |
| `extra` | стыки кромок с hideOnBlur, перепривязкой и выходом |
| `off` | `handles=false`: кромок нет вовсе, остальное работает как раньше |

`apps` — нужны настоящие программы, поэтому в VM их сначала надо
поставить. На чистой машине этот набор пропускать.

| набор | что меряет |
|---|---|
| `apps` | VS Code, Telegram, Chrome: показ, анимация, парковка, контекстное меню Telegram |
| `browser` | окно Chrome целиком: показ, уборка, возврат при выходе |

Набор `quiet` пересобирает исходник, дописывая в `Notify()` строку в
файл: `TrayTip` — не окно, снаружи его не увидеть. С `-Exe` этот набор
пропускается.

## Файлы

```
run.ps1              единственная точка входа
layout.ahk           раскладка мониторов и приговор ГОДИТСЯ/НЕ ГОДИТСЯ
strand.ahk           не осталось ли окон за пределами экранов
sendhk.ahk           отправить хоткей (SendLevel 1 — иначе чужой скрипт его не увидит)
drivers/*.ahk        сами тесты
benches/*/config.ini конфиги стендов
```

Драйвер пишет в лог строки `ok` / `БАГ` и заканчивает строкой `ИТОГ`.
`run.ps1` считает набор провалившимся, если итога нет, в нём не «провалов
0» или в логе есть `ОШИБКА`.

## Ловушки, на которые уже наступали

**`SendLevel(1)` обязателен** в любом скрипте, который шлёт хоткеи
ящику. Без него клавиши одного AHK-скрипта не вызывают хоткеи другого, и
весь прогон радостно проходит, ничего не сделав.

**Имена в AHK регистронезависимы.** `MonitorGetWorkArea(mi, &L, &T, &R, &B)`
затирает параметр с именем `r`. Так же ломаются `log` (`Log()`) и `exp`
(`Exp()`).

**`WaitStable` спит перед первым замером.** Кромка начинает расти не
раньше очередного тика опроса, и без паузы «стабильным» окажется ещё не
начавший меняться размер.

**Номер слота лежит не в `Static1`.** Иконка добавляется в плитку
первой, поэтому номер оказался во втором контроле. Драйвер ищет тот
контрол, у которого непустой текст, а не фиксированное имя класса.

**Не считать тест пройденным потому, что код выглядит логичным.** Здесь
уже были: трекер, следивший только за X (для верхнего и нижнего краёв
движение идёт по Y), предусловие, не отличавшее «окно на своём месте» от
«окно выдвинуто», и две проверки вида `!OnScreen(B) = false || true`,
которые не проверяли ничего.
