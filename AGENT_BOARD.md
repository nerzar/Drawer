## Что делать дальше

После запуска в чистом сеансе архитектор должен:

1. Прочитать актуальные документы и посмотреть фактическое состояние `master`.
2. Сверить известные баги, roadmap и доступных исполнителей.
3. Самостоятельно подумать, какой следующий небольшой шаг даст больше пользы и меньше риска.
4. Не считать последнюю обсуждавшуюся тему автоматически следующей задачей.
5. Если следующий шаг технически очевиден и не меняет продуктовый смысл — подготовить небольшую задачу подходящему исполнителю.
6. Если есть архитектурная развилка или требуется продуктовое решение — коротко объяснить владельцу варианты и дать рекомендацию.

DWM Thumbnail PoC (`docs/agent-tasks/RUN-20260908-ANTIGRAVITY-DWM-THUMBNAIL-POC-01.md`) — один из кандидатов, а не уже выбранный следующий шаг.

## Правила текущей работы

- Делать изменения небольшими проверяемыми кусками.
- Не плодить ветки, worktree, документы, тестовые круги и взаимопроверки без понятной пользы.
- Git вести аккуратно; после завершённой работы безопасно убирать временные ветки/worktree.
- После неудачной ручной проверки сначала разобраться с наблюдаемой регрессией, а не накладывать сверху новый рефакторинг.
- Runtime-тесты по умолчанию выполнять в подготовленной VM. На основной Windows владельца `drawer.ahk` и runtime-тесты не запускать без прямого запроса.
