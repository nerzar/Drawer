## Что делать дальше

Архитектор **не должен автоматически превращать этот раздел в очередную задачу**.

После запуска в чистом сеансе он должен:

1. Прочитать документы выше и посмотреть фактическое состояние `master` и незавершённой работы в Git.
2. Сверить известные баги, roadmap и доступных исполнителей.
3. Самостоятельно подумать, какой следующий шаг даст проекту больше пользы и меньше риска. Не считать, что последняя обсуждавшаяся тема автоматически самая важная.
4. Если следующий шаг технически очевиден и не меняет продуктовый смысл — можно подготовить небольшую задачу подходящему исполнителю.
5. Если есть несколько существенно разных направлений, архитектурная развилка или требуется продуктовое решение — коротко объяснить владельцу варианты и предложить рекомендацию.

Цель архитектора — снять с владельца постоянное диспетчерское управление проектом, но не принимать за него продуктовые решения.

## Правила текущей работы

- Делать изменения небольшими проверяемыми кусками.
- Не плодить ветки, worktree, документы, тестовые круги и взаимопроверки без понятной пользы.
- Git вести аккуратно; после завершённой работы безопасно убирать временные ветки/worktree.
- После неудачной ручной проверки сначала разобраться с наблюдаемой регрессией, а не накладывать сверху новый рефакторинг.
- Для реального поведения Windows использовать короткую ручную проверку владельца, когда она быстрее и надёжнее очередного круга агентских тестов.
