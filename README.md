# Ящик

Выезжающая панель для окон Windows. Хоткей выдвигает окно приложения
сбоку экрана поверх остальных, повторный хоткей убирает его за край.
Окно не закрывается и не сворачивается — состояние сохраняется.

Написано после того, как WTQ на этой машине оказался нерабочим:
он падал на свёрнутых окнах, зависал на служебных окнах PhpStorm,
а зависший экземпляр блокировал все последующие запуски.

## Запуск

Нужен AutoHotkey v2. Запускается двойным щелчком по `src\drawer.ahk`
или ярлыком на рабочем столе.

| Хоткей | Действие |
|---|---|
| `Ctrl+Alt+1…9` | выдвинуть / убрать окно слота |
| `Ctrl+Alt+Shift+1…9` | запомнить в слоте текущее активное окно |
| `Ctrl+Alt+0` | очистить динамические слоты, окна вернутся на исходные места |
| `Ctrl+Alt+Shift+0` | выход из программы, окна вернутся на исходные места |
| `Ctrl+Alt+Win+1…2` | вернуть фокус в постоянный слот |

Слоты 1 и 2 по умолчанию заняты VS Code и PhpStorm, слоты 3–9 свободны.

Второй запуск не конфликтует с первым: новый экземпляр вытесняет старый.
При запуске программа показывает уведомление «Ящик запущен, хоткеев
живо: N» — если уведомления нет или число меньше ожидаемого, значит
хоткеи не встали.

Хоткеи ставятся через клавиатурный хук, а не `RegisterHotkey`: иначе
сочетание может молча остаться за не успевшим умереть экземпляром, и
программа работает без клавиш.

## Слоты

Единица управления — слот с номером от 1 до 9. Номер задаёт клавиши, и
это единственное, что их задаёт.

**Постоянный слот** описан в настройках: приложение ищется по имени
процесса при каждом нажатии, переживает перезапуск программы. Такой
слот защищён — `Ctrl+Alt+Shift+N` его не перезапишет, а скажет, что он
занят.

**Динамический слот** пуст до тех пор, пока вы не назначите в него окно
через `Ctrl+Alt+Shift+N`. Запоминается конкретное окно, а не приложение:
из пяти окон Chrome слотом станет ровно то, что было активно. Переход в
другое приложение и курсор на другом мониторе выбор не меняют.

Назначить окно в занятый динамический слот можно в любой момент —
прежнее окно вернётся на исходное место, слот начнёт управлять новым.

`Ctrl+Alt+0` очищает все динамические слоты сразу: окна возвращаются на
исходные места, привязки забываются, программа продолжает работать.
Постоянные слоты это не затрагивает.

Динамические привязки живут только пока работает программа — после
перезапуска слоты 3–9 снова пусты.

## Настройка

Всё в начале `src\drawer.ahk`, в блоке `НАСТРОЙКИ`. Массив `apps`
задаёт постоянные слоты, по одной записи на приложение:

| Поле | Значение |
|---|---|
| `slot` | номер слота, 1…9 — им же задаётся хоткей |
| `exe` | имя процесса, например `Code.exe` |
| `cls` | класс окна; `""` если не важен |
| `focusHotkey` | вернуть фокус: выдвинуть, если спрятано, и активировать; `""` выключает |
| `monitor` | `"cursor"` — монитор под курсором, либо номер: `1`, `2`, `3`… |
| `edge` | `"left"`, `"right"`, `"top"`, `"bottom"` |
| `width` | размер панели в процентах рабочей области монитора: для `left`/`right` — ширина, для `top`/`bottom` — высота |
| `activateOnShow` | делать окно активным при выезде |
| `hideOnBlur` | убирать панель, когда фокус ушёл в другое окно |

Блок `dynamic` задаёт те же поля сразу для всех динамических слотов.
Настройки отдельного слота можно положить в `dynamicSlots`, например
`dynamicSlots[5] := { edge: "left", width: 40 }` — незаданные поля
возьмутся из `dynamic`.

`animMs` и `animSteps` управляют анимацией, `animSteps := 0` выключает
её. `blurMs` — как часто проверяется потеря фокуса.

После правки перезапустить скрипт.

## Поведение панели

`activateOnShow: true` — панель выезжает и забирает фокус.
`activateOnShow: false` — панель выезжает поверх остальных окон, но
работать вы продолжаете там, где работали.

`hideOnBlur: true` — панель уезжает сама, как только фокус ушёл в другое
окно. `false` — остаётся, пока не уберёте хоткеем.

Пара `activateOnShow: false` + `hideOnBlur: true` смысла не имеет: окно,
которому не давали фокуса, потерять его не может — слежение в этом
случае не включается.

Слежение за фокусом — таймер на 250 мс, и он работает только пока
выдвинуто окно с `hideOnBlur`. Когда все панели убраны, программа не
делает ничего.

`focusHotkey` нужен потому, что хоткей слота — переключатель: если
панель выдвинута, но вы ушли в другое окно, `Ctrl+Alt+N` её уберёт, а
`Ctrl+Alt+Win+N` вернёт вас в неё. Он есть только у постоянных слотов:
`Ctrl+Alt+Shift+N` теперь назначает окно в слот.

## Alt+Tab и панель задач

Припаркованное окно остаётся обычным окном Windows: оно есть в Alt+Tab и
на панели задач. Переключитесь на него любым способом — оно выедет
панелью само. Программа слушает событие активации окна и возвращает на
экран только то, что сама же и припарковала; чужие окна и уже выдвинутые
панели она не трогает.

Выезд происходит, только когда панель выбрали. Если вы свернули или
закрыли своё окно и Windows передала фокус дальше по цепочке, панель не
появится: её никто не звал.

Когда панель убирается хоткеем, фокус возвращается тому окну, в котором
вы работали до её появления. Если панель уехала сама по `hideOnBlur`,
фокус не трогается — вы уже щёлкнули туда, куда хотели.

## Край, монитор и парковка

Край берётся из настройки как есть: программа не переворачивает `right`
в `left`, даже если справа стоит другой монитор. Монитор берётся из
настройки — под курсором или по номеру. Число мониторов, их расположение
и разрешения нигде не предполагаются: геометрия каждый раз запрашивается
у Windows.

Спрятанное окно паркуется за границей всего виртуального рабочего
стола, поэтому спрятать его за любой край можно всегда. Намеренно не
используется `WinHide`: скрытое им окно после аварийного завершения
программы вернуть штатными средствами Windows нельзя, а припаркованное —
находится и возвращается при следующем запуске.

Анимация уводит окно за край монитора. Если к выбранному краю примыкает
другой монитор, окно проехало бы по нему на виду — в этом случае
анимация пропускается и окно паркуется сразу.

## Известные ограничения

- При нескольких окнах одного приложения постоянный слот берёт окно
  наибольшей площади. Динамический этим не страдает: он помнит
  конкретное окно.
- Динамические слоты забываются при перезапуске программы.
- Освободить один слот отдельно нельзя — только очистить все
  динамические сразу.
- Если к выбранному краю примыкает другой монитор, выезд и уезд без
  анимации, рывком.
- Края `top` и `bottom` реализованы, но вживую не проверялись.
- Мониторы с разным масштабом (DPI) не проверялись.
- Автозапуска нет: программа запускается вручную.
- Окно остаётся в Alt+Tab и на панели задач.
