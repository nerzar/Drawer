## Этап 1 — закончить Settings

Архитектурный gate Claude — **GO** для modular monolith + центральной
runtime-модели Slot. Production-база — `a39f543`; integration-контракт —
`docs/settings-integration-layer.md`, принятое решение — Р20.
Seam Save уже существует; перенос в модули не создаёт второй persistence path.

### Принятый порядок commit'ов

`C1 stable Slot ID → C2 service-window registry → C3 structured SlotStatus → C4 Save outcome → C5 headless validation/config → WebView bridge → C6 native picker parity fix`

C1–C6, bridge и оставшиеся части (slotEdits, picker, bind/release,
watchStatus, conversion) реализованы. Из этапа 1 остаётся приёмка S4
(«Приёмка Settings» ниже): целевые сценарии редактирования постоянных
слотов, выбора exe/окна и переходов Dynamic ↔ Permanent в VM. Полный
перенос монолита по файлам, устранение всех globals и расширение числа
слотов в этот gate не входили и делаются этапом 2.
Каждый этап — отдельное проверяемое изменение; VM нужна для сценариев,
управляющих реальными окнами/фокусом, а не для docs или чистого plan/config.

### Приёмка Settings

- Проверить редактирование постоянных слотов, выбор exe/окна и переходы
  Dynamic ↔ Permanent отдельным целевым сценарием. Хоткей постоянного
  слота покрыт: `settings-seam` точка 18 и `webview-slice` 7a–7f.
- Оставить `config.ini` единственным источником постоянных настроек:
  Settings читает и изменяет тот же файл.
- Отделить UI-представление от внутренних значений конфига. Вместо
  `right`, `cursor`, `true` пользователь должен видеть понятные подписи,
  а преобразование должно происходить на границе Settings и конфига.
- Порядок persist → reconcile реализован в `4844486`; в `a39f543`
  исправлены сверка удаления и Release динамической привязки по
  фактическому переходу; C4 довёл structured partial-failure outcome.
- После проверки сократить повторяющееся описание полей слота в загрузке,
  GUI, валидации и записи.

## Этап 2 — модульный монолит

Сделано (Р22, `src/Slots.ahk`):

- `Slot` — центральная сущность runtime-модели; идентичность слота — его
  номер, позиционной идентичности в программе не осталось;
- параллельные структуры `apps`, `permSlots`, `managed`, `dynSlots`,
  `dynamicSlots` и глобальный `dynamic` сведены в одну запись реестра;
- разные lifecycle-типы сохранены: permanent живёт в `config.ini` и ищет
  окно по `exe` и необязательному `cls`; dynamic привязан к конкретному
  HWND только в текущей сессии;
- общие действия над слотом вынесены в единый API, которым пользуются
  hotkeys, кромки, native Settings и WebView-порт;
- загрузка конфига отделена от рантайма: `LoadConfig` возвращает объект,
  `ConfigApply` и `Slots.Apply` его проецируют.

Осталось:

- Вынести из `src/drawer.ahk` оконную модель (`state`, `watched`,
  `Show`/`Hide`, геометрия, фокус) и кромки — по одному seam за раз, без
  изменения поведения. Цель та же: меньше связности, меньше контекста
  AI-агенту, меньше риска случайных изменений и меньше diff.
- Ориентировочные оставшиеся модули: `windows/focus`, `parking`,
  `handles`, `settings`, `tray`.
- Не ограничиваться переносом функций по файлам: у каждого модуля должны
  появиться явная граница и короткий контракт.

## Отложенные возможности

### Выбор конкретного окна постоянного слота — F12

Текущий picker заполняет `exe` и `cls`, но постоянный слот по-прежнему
ищет окно процесса и при нескольких кандидатах выбирает самое большое.
Отбор по заголовку или запоминание последнего активного окна требуют
отдельного решения.

### Исключение припаркованного окна из Alt+Tab — F8

Потребуется временно менять `WS_EX_TOOLWINDOW` и гарантированно возвращать
стиль при штатном и аварийном завершении. Риск нарушения N4 выше текущей
пользы.

### Освобождение одного динамического слота — F13

Реализовано через `SlotRelease(n)` / `slot.release`: динамический слот возвращает
окно на исходное место, снимает привязку с записи слота в реестре,
пересобирает кромки и отвечает актуальным `SlotStatus` и каноническим
`SettingsState`.

### Автозапуск — F11

Откладывается до длительной ручной эксплуатации стабильной сборки.
