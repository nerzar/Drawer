# План работ

Документ содержит только незавершённые направления. Реализованные
решения и их причины находятся в `03-решения.md`, состояние репозитория —
в `PROJECT_STATE.md`, тестовое покрытие — в `test/README.md`.

## Порядок развития

1. Закончить Settings через принятый gate: C1–C5 → WebView bridge → C6.
2. Выполнить модульный structural refactor без изменения поведения.
3. После стабилизации границ добавить произвольные слоты и новые
   UI-действия.

## Этап 1 — закончить Settings

Архитектурный gate Claude — **GO** для modular monolith + центральной
runtime-модели Slot. Production-база — `a39f543`; integration-контракт —
`docs/settings-integration-layer.md`, принятое решение — Р20.
Seam Save уже существует; перенос в модули не создаёт второй persistence path.

### Принятый порядок commit'ов

`C1 stable Slot ID → C2 service-window registry → C3 structured SlotStatus → C4 Save outcome → C5 headless validation/config → WebView bridge → C6 native picker parity fix`

| Этап | Граница изменения | Минимальная проверка |
|---|---|---|
| C1 stable Slot ID | Callback и slot API используют номер 1–9, а не индекс `apps`; focus callback разрешает актуальный `permSlots` при вызове. Изменение самого `focusHotkey` по-прежнему требует restart. | После conversion раннего Permanent-слота focus hotkey соседнего обращается к прежнему номеру. |
| C2 service-window registry | Убрать знание `setGui`/`setPickerGui` из оконного core; native Settings, будущий WebView host и диалоги регистрируются как служебные. Сохранить текущие фильтры фокуса. | Settings/picker нельзя bind; переход в них не вызывает hideOnBlur. |
| C3 structured SlotStatus | Единый read-only enum + title для native и WebView; не разбирать русские строки `SettingsSlotStatus`, не захватывать окна при чтении статуса. | Пять состояний из ADR, отсутствие записи в `managed` при просмотре. |
| C4 Save outcome | Поверх существующего pipeline вернуть structured success/error и partial/reload metadata; учесть ошибки writes/deletes/readback/reconciliation. Никакой второй реализации persistence и обещания rollback. | No-op, success, failure до/после мутации, успешный/неуспешный reload; draft не теряется. |
| C5 headless validation/config | Общая backend-валидация semantic input и загрузка config без GUI-controls/MsgBox; native отображает возвращённые diagnostics. Сохранить defaults, точечную запись и нетронутые значения. | Невалидный DTO отклоняется до записи; UTF-16 LE, комментарии и отсутствующие ключи сохраняются. |
| WebView bridge | Подключить semantic port к тому же Save, status и registry; перенести проверенный lifecycle/picker gate из spike. | Apply/OK/Cancel, close timeout, busy во время picker, cleanup после выхода picker; целевой S4. |
| C6 native picker parity fix | После bridge выровнять native picker по принятому lifecycle/reentrancy-контракту; не менять правило выбора Permanent по exe/cls. | Close/Cancel и повторные действия во время native picker; один cleanup после возврата picker. |

C1–C5 выполнены. C6 выполняется **после** bridge
и не переносится в pre-WebView gate. Полный перенос монолита по файлам,
устранение всех globals и расширение числа слотов не входят в этот gate.
Каждый этап — отдельное проверяемое изменение; VM нужна для сценариев,
управляющих реальными окнами/фокусом, а не для docs или чистого plan/config.

### Приёмка Settings

- Проверить редактирование постоянных слотов, выбор exe/окна и переходы
  Dynamic ↔ Permanent отдельным целевым сценарием.
- Оставить `config.ini` единственным источником постоянных настроек:
  Settings читает и изменяет тот же файл.
- Отделить UI-представление от внутренних значений конфига. Вместо
  `right`, `cursor`, `true` пользователь должен видеть понятные подписи,
  а преобразование должно происходить на границе Settings и конфига.
- Порядок persist → reconcile реализован в `4844486`; в `a39f543`
  исправлены сверка удаления и Release динамической привязки по
  фактическому переходу; C4 довёл structured partial-failure outcome.
- После проверки сократить повторяющееся описание полей слота в загрузке,
  GUI, валидации и записи.

## Этап 2 — модульный монолит

- Постепенно разделить `src/drawer.ahk` по одному seam за раз без
  изменения поведения. Цель — уменьшить связность, необходимый
  AI-агентам контекст, риск случайных изменений и размер diff'ов.
- Ориентировочные модули: `main`, `config`, `slots`, `windows/focus`,
  `parking`, `handles`, `settings`, `tray`.
- Не ограничиваться переносом функций по файлам: у каждого модуля должны
  появиться явная граница и короткий контракт.
- Сделать `Slot` центральной сущностью runtime-модели и постепенно
  отказаться от `apps index` как идентичности.
- Сохранить разные lifecycle-типы слотов:
  - permanent сохраняется между сессиями и ищет окно по `exe` и
    необязательному `cls`;
  - dynamic может быть перебинден на конкретный HWND, но эта привязка
    живёт только в текущей сессии и не сохраняется после перезапуска.
- Вынести общие действия в единый slot API/command layer, которым
  пользуются hotkeys, handles, tray и Settings.

## Этап 3 — произвольные слоты и действия

- Убрать фундаментальный лимит 1–9 и поддержать произвольное количество
  слотов.
- Добавить в Settings команды «Добавить слот» и «Удалить слот».
- Сделать hotkey свойством слота. Для существующих слотов сохранить
  `Ctrl+Alt+1…9` как дефолты и совместимое поведение.
- Добавить контекстное меню действий слота по ПКМ на кромке.
- Расширить tray menu командами управления слотами и общими действиями.
- Добавить два независимых действия: сброс слотов и полный сброс всех
  настроек Drawer к значениям по умолчанию.
- Не добавлять отдельный `enabled`: отсутствие hotkey уже отключает слот.
- Поиск и фильтр слотов, а также Hide all / Show all на этом этапе не
  нужны.

## Отложенные возможности

### Выбор конкретного окна постоянного слота — F12

Текущий picker заполняет `exe` и `cls`, но постоянный слот по-прежнему
ищет окно процесса и при нескольких кандидатах выбирает самое большое.
Отбор по заголовку или запоминание последнего активного окна требуют
отдельного решения.

### Исключение припаркованного окна из Alt+Tab — F8

Потребуется временно менять `WS_EX_TOOLWINDOW` и гарантированно возвращать
стиль при штатном и аварийном завершении. Риск нарушения N4 выше текущей
пользы.

### Освобождение одного динамического слота — F13

Сейчас `Ctrl+Alt+0` очищает все динамические слоты. Отдельная команда
должна также определить поведение окна, назначенного сразу в несколько
слотов.

### Автозапуск — F11

Откладывается до длительной ручной эксплуатации стабильной сборки.
