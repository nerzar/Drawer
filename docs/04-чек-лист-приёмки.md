# Чек-лист приёмки

Список составлен не из головы, а по реальным отказам предшественника.
Прогонять целиком после каждого изменения, затрагивающего работу с окнами.

| № | Сценарий | Как проверять | Статус |
|---|---|---|---|
| П1 | Второй экземпляр не блокирует запуск | запустить программу дважды подряд, убедиться что процесс один и хоткеи живы | пройден |
| П2 | Свёрнутое окно | свернуть окно вручную, нажать хоткей — окно должно развернуться и выехать | пройден |
| П3 | Служебное окно без заголовка | запустить PhpStorm и жать хоткей во время загрузки проекта | пройден |
| П4 | Приложение не запущено | нажать хоткей приложения, которое не запущено — уведомление, программа жива | пройден |
| П5 | Выход возвращает окна | спрятать окно, выйти по `Ctrl+Alt+Shift+0`, проверить исходные координаты | пройден |
| П6 | Настройки не теряются | перезапустить программу, проверить что настройки на месте | пройден |
| П7 | Работа после перезагрузки | ребут, запуск ярлыка, проверка обоих хоткеев | **не проверен** |
| П8 | Второй монитор | увести курсор на другой монитор и вызвать панель там | пройден |
| П9 | Край не переворачивается | на мониторе, справа от которого стоит другой экран, при `edge: "right"` панель обязана выехать справа и спрятаться вправо | **не проверен** |
| П10 | Монитор по номеру | задать `monitor: 2`, вызвать хоткей с курсором на другом мониторе — панель на мониторе 2 | **не проверен** |
| П11 | Отключённый монитор | задать номер несуществующего монитора — панель выезжает на мониторе под курсором, программа жива | **не проверен** |
| П12 | Перезапуск при спрятанном окне | спрятать окно, снять процесс через диспетчер задач, запустить снова, нажать хоткей, затем выйти по `Ctrl+Alt+Shift+0` — окно должно остаться на экране, а не уехать за него | **не проверен** |
| П13 | Окно сдвинуто руками | выдвинуть панель, перетащить окно мышью, нажать хоткей — окно возвращается на место панели, а не прячется | **не проверен** |
| П14 | Края `top` и `bottom` | задать `edge: "top"`, затем `edge: "bottom"` — панель выезжает сверху и снизу, размер считается по высоте | **не проверен** |
| П15 | Хоткеи живы после перезапуска поверх работающего экземпляра | запустить программу, не закрывая её запустить ещё раз, сразу нажать хоткей | пройден |
| П16 | Пустой слот | нажать `Ctrl+Alt+3`, ничего не назначив — уведомление, ничего не двигается, программа жива | пройден |
| П17 | Назначение слота | встать в окно, `Ctrl+Alt+Shift+3`, затем `Ctrl+Alt+3` — окно выезжает | пройден |
| П18 | Слот держит именно это окно | активировать второе окно того же приложения и нажать `Ctrl+Alt+3` — управляется первое | пройден |
| П19 | Перепривязка слота | из другого окна нажать `Ctrl+Alt+Shift+3` — прежнее окно возвращается на исходное место, слот управляет новым | пройден |
| П20 | Очистка слотов | `Ctrl+Alt+0` — окна на исходных местах, слоты пусты, программа работает, постоянные слоты не тронуты | пройден |
| П20а | Постоянный слот защищён | `Ctrl+Alt+Shift+1` при занятом слоте — уведомление, привязка не меняется | пройден |
| П20б | Слоты независимы | назначить разные окна в слоты 4 и 5, переключать по очереди | пройден |
| П20в | Слоты после перезапуска | назначить слот, выйти, запустить снова — динамические слоты пусты, постоянные работают | пройден |
| П21 | `activateOnShow: true` | нажать хоткей — окно выезжает и становится активным | пройден |
| П22 | `activateOnShow: false` | нажать хоткей, находясь в другом окне — панель выезжает, активным остаётся то, в котором работали | пройден |
| П23 | `hideOnBlur: true` | выдвинуть панель, щёлкнуть в другое окно — панель уезжает сама | пройден |
| П24 | `hideOnBlur: false` | то же самое — панель остаётся выдвинутой, убирается только хоткеем | пройден |
| П25 | `focusHotkey` | из спрятанного состояния — выдвигает и активирует; из выдвинутого — только активирует, не двигая окно | пройден |
| П27 | Фокус после уборки | работать в окне, выдвинуть панель, убрать хоткеем — активным становится то окно, где работали | пройден |
| П28 | Убранное окно не активно | после уборки припаркованное окно не должно быть foreground | пройден |
| П29 | Alt+Tab на припаркованное окно | переключиться на него из Alt+Tab — окно выезжает | пройден |
| П30 | Панель задач | щёлкнуть по значку припаркованного приложения — окно выезжает | пройден вживую |
| П31 | Выдвинутое окно не дёргается | Alt+Tab на уже выдвинутую панель — координаты не меняются | пройден |
| П32 | Обычные окна | переключаться между чужими окнами — Ящик не вмешивается | пройден |
| П33 | Активация и `hideOnBlur: true` | выдвинуть по Alt+Tab при `hideOnBlur: true` — панель остаётся, цикла «показать — спрятать» нет | пройден |
| П34 | Сворачивание чужого окна | свернуть любую другую программу — панель НЕ должна выехать | пройден |
| П35 | Закрытие чужого окна | закрыть окно — панель НЕ должна выехать | пройден |
| П36 | Другое окно того же приложения | активировать соседнее окно того же процесса — панель НЕ должна выехать | пройден |

## Прогон Alt+Tab

Автопрогон на трёх собственных окнах: A — окно слота, B и C — соседние.
Панель паркуется уходом фокуса (`hideOnBlur`), затем нажимается живой
Alt+Tab. Каждый сценарий прогнан и для постоянного слота, и для
динамического.

| Проверка | До правки | После правки |
|---|---|---|
| Alt+Tab на припаркованное окно | 0 выездов из 5 | 5 из 5, окно активно |
| Alt+Tab между обычными окнами | — | активно C, панель на `1940,0` |
| два окна одного процесса | — | выехало именно окно слота, соседнее не тронуто |
| сворачивание чужого окна | — | панель на `1940,0`, активна не она |
| панель задач (`SwitchToThisWindow`) | работало | работает, `768,0` |
| закрытие чужого окна поверх панели | — | панель на `1940,0`, активна не она |
| `hideOnBlur` при уходе в соседнее окно | работало | работает, панель уехала |
| уборка панели, выехавшей по Alt+Tab | — | фокус вернулся в B |
| `Ctrl+Alt+0` после всего | — | окно на исходном месте |

Итог: 9 из 9 для динамического слота, 8 из 8 для постоянного (у
постоянного нет очистки слотов). Тот же прогон на боевом
`src/drawer.ahk` без правок — 9 из 9.

## Прогон настроек поведения

Два автопрогона на Блокноте (постоянный ящик) и двух окнах Windows
Terminal (динамический слот), с зеркальными настройками.

Прогон А — постоянный слот `true/true`, динамический `false/false`:

| Шаг | Результат |
|---|---|
| хоткей постоянного | `1152,0`, окно активно |
| фокус ушёл в другое окно | через 1,5 с панель на `1940,0` |
| `focusHotkey` из спрятанного | `1152,0`, окно активно |
| `focusHotkey` повторно | координаты те же, окно активно |
| динамический из другого окна | `1152,0`, активным осталось другое окно |
| через 2 с без фокуса | всё ещё `1152,0` |
| возврат фокуса | окно стало активным |
| закрыть запомненное окно, нажать оба хоткея | привязка сброшена, падения нет |
| выход | окна на исходных местах |

Прогон Б — настройки зеркально (постоянный `false/false`, динамический
`true/true`): панель постоянного слота выехала, не забирая фокус, и
осталась висеть; динамический уехал сам, как только фокус ушёл.

## Прогон динамической привязки

Автоматический прогон: постоянный бинд на Блокноте (монитор 1, `right`,
40 %), динамический — на двух окнах Windows Terminal одного процесса.

| Шаг | Результат |
|---|---|
| постоянный бинд: выдвинуть / спрятать Блокнот | `1152,0 768×1032` → `1940,0` |
| динамическая привязка: запомнить окно A | A выдвинуто, B не тронуто |
| активировать окно B того же процесса, нажать хоткей | убрано **A** (`1940,4`), B не тронуто |
| курсор на монитор 2, нажать хоткей | выдвинуто **A** на мониторе 2 (`-768,4`) |
| закрыть окно A, нажать хоткей | привязка сброшена, падения нет, B не тронуто |
| нажать хоткей с активным B | запомнено B, выдвинуто на мониторе под курсором (`1152,0`) |
| выход | Блокнот и B на исходных местах |

Этим же прогоном найдена ошибка выбора монитора по курсору: см. Р8,
`CoordMode("Mouse", "Screen")`.

## Ловушка при тестировании

У VS Code открыто несколько окон. Программа берёт окно наибольшей
площади, а `Process.MainWindowHandle` в PowerShell возвращает другое.
Из-за этого один прогон выглядел как провал, хотя программа работала
правильно. Измерять нужно тот дескриптор, который программа реально
захватила, — его видно в отладочном журнале.
