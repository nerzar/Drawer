# Переезд архитектора — 8 сентября 2026

## Зачем переезжаем

Старый диалог стал слишком большим: в нём смешались актуальные решения, отменённые идеи, временные гипотезы, результаты агентов и обсуждения других тем. Это уже приводило к тому, что старые технические решения принимались за актуальное поведение продукта.

Новый архитектор не должен восстанавливать состояние проекта из всей истории чата.

## Что переносим

В Git:
- текущее состояние кода;
- `PRODUCT_SPEC.md`;
- актуальную доску задач;
- task/claim/report как техническую историю;
- короткие файлы из `docs/architect/`.

В долговременную память:
- устойчивые правила работы владельца;
- важные причины решений, которые плохо видны из кода;
- ошибки процесса, которые нельзя повторять;
- важные результаты ручных проверок и предпочтения по взаимодействию.

Не переносим в память целиком:
- старые логи агентов;
- списки веток и SHA, которые можно получить из Git;
- временные READY/WAITING статусы;
- каждую промежуточную гипотезу ночной отладки.

## Главный урок последней волны

Несколько технически аккуратных рефакторингов и зелёных тестов вместе изменили реальное поведение Drawer. Затем попытки чинить это по отчётам агентов породили дополнительные изменения продукта. Поэтому поведение сначала фиксируется в `PRODUCT_SPEC.md`; при неоднозначности архитектор спрашивает владельца; runtime-sensitive изменения проверяются на реальной системе небольшими шагами.

## Старт нового сеанса

Новый архитектор сначала читает `docs/architect/ARCHITECT_BOOTSTRAP.md`, затем `PRODUCT_SPEC.md`, `PROJECT_STATE.md` и свежий `AGENT_BOARD.md`. После этого сверяет актуальный Git и только потом формирует задачи.
