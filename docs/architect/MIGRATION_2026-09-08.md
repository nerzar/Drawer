# Переезд архитектора — 8 сентября 2026

## Зачем переезжаем

Старый диалог стал слишком большим: в нём смешались актуальные решения, отменённые идеи, временные гипотезы, результаты агентов и посторонние обсуждения. Это уже приводило к тому, что старые технические решения принимались за актуальное поведение продукта.

Новый архитектор не должен восстанавливать состояние проекта из всей истории чата или читать весь архив агентов подряд.

## Что является актуальным

В Git:
- текущий код `master`;
- `docs/PRODUCT_SPEC.md`;
- `docs/05-план-работ.md`;
- `docs/architect/*`;
- свежий `AGENT_BOARD.md`;
- task/claim/report только для текущей задачи.

В долговременной памяти:
- устойчивые правила работы владельца;
- причины важных решений, которые плохо видны из кода;
- уроки серьёзных ошибок и регрессий;
- устойчивые предпочтения по процессу.

Не хранить в памяти и не тащить в новый контекст без причины:
- старые логи и отчёты агентов;
- списки веток и SHA;
- временные READY/WAITING статусы;
- промежуточные гипотезы отладки;
- посторонние темы.

## Главный урок переезда

Архитектору нужен чистый рабочий контекст. Не держать в одном бесконечном диалоге проект, сторонние вопросы и всю историю каждого агента. Текущее состояние брать из Git, продуктовые решения — из `PRODUCT_SPEC.md` и свежих решений владельца, устойчивые правила — из Hindsight.

Процесс нельзя отпускать надолго без контроля: изменения делаются небольшими кусками, после значимого результата сверяется фактическое состояние, и следующая волна не строится поверх непроверенного runtime-поведения.

Технически аккуратный рефакторинг и зелёные тесты сами по себе не гарантируют правильное поведение Drawer. При неоднозначности нужно спросить владельца; сложное Windows-поведение проверять небольшими шагами.

## Старт нового сеанса

Новый архитектор сначала читает `docs/architect/ARCHITECT_BOOTSTRAP.md` и указанные там актуальные файлы. Старые `docs/agent-*` использует только адресно, если нужно расследовать конкретную историю изменения. После этого сверяет фактический Git и предлагает осмысленный следующий шаг, а не автоматически продолжает последнюю старую очередь.
