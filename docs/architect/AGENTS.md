# Drawer — кто за что отвечает

Этот файл помогает архитектору выбирать подходящего исполнителя, а не раздавать задачи по принципу «кто сейчас свободен».

## Claude Sonnet — основной программист №1

Сейчас доступен без ограничения по лимиту. Основной исполнитель для разработки Drawer: реализация функций, исправление сложных багов, технические исследования и прототипы.

При этом токены Claude всё равно нужно беречь: если задача нормально решается бесплатным/дешёвым исполнителем без потери качества, лучше отдать её туда.

Если задача сложная, но её можно нормально сформулировать и проверить небольшим результатом, сначала пробовать Sonnet.

## Codex / ChatGPT Sol — основной программист в Codex

Основная часть работы внутри Codex должна выполняться этим отдельным coding-сеансом, а не самим архитектором.

Архитектор может сам ненадолго вмешиваться в работу Codex, когда ему нужно напрямую разобраться в репозитории или решить архитектурный вопрос, но не должен постоянно расходовать свой лимит на обычное программирование.

Ориентир по общему лимиту Codex: coding-сеанс может расходовать его примерно до остатка 30%. Последние около 30% нужно беречь для архитектора, чтобы он не потерял возможность управлять проектом, разбирать сложные ситуации и поддерживать очередь.

## Antigravity / Gemini — основной программист №2

Подходит для параллельных хорошо ограниченных задач, исправлений, прототипов и реализации уже понятного решения.

Лимит Antigravity специально экономить не нужно: при наличии полезной работы он может работать постоянно, в том числе круглосуточно.

Не поручать ему самостоятельно придумывать новое продуктовое поведение, если требование неоднозначно.

## OpenCode

OpenCode также не относится к дефицитным ресурсам. Его можно активно использовать для подходящих задач, особенно если это позволяет не расходовать Claude/Codex.

Конкретную модель внутри OpenCode выбирать по характеру задачи.

## Claude Opus — техлид для сложных случаев

Использовать, когда Sonnet/Gemini/Codex упёрлись, есть серьёзная техническая развилка или нужен особенно глубокий разбор проблемы. Не тратить Opus на обычную реализацию без причины.

## Muse 1.3 — быстрый вспомогательный агент

Доступен постоянно 24/7. Хорош для узкого анализа, поиска ошибок, небольших задач и недорогих проверок. При необходимости может быть заменён DeepSeek.

## ChatGPT — независимый reviewer и бесплатный помощник

Пользователь может подключать отдельный ChatGPT-чат для независимого разбора существенных изменений, спорных решений, больших merge и ситуации в проекте в целом.

Если задача не требует расходовать дефицитные лимиты Claude/Codex и её можно нормально решить здесь — лучше использовать ChatGPT. Не требуется прогонять через reviewer каждую мелкую правку.

## Пользователь — владелец продукта

Пользователь принимает решения о поведении Drawer и быстро проверяет на реальной Windows то, что трудно надёжно оценить автоматическими тестами: окна, фокус, кромки, анимации, Alt+Tab/taskbar и несколько мониторов.

Пользователь не обязан постоянно держать в голове весь roadmap и самостоятельно выбирать следующую техническую задачу. Архитектор должен анализировать текущее состояние проекта, зависимости, риски и доступных исполнителей и предлагать осмысленный следующий шаг. Если следующий шаг затрагивает продуктовое решение или есть несколько существенно разных направлений — коротко обсудить выбор с пользователем.

## Общее правило

Сначала понять характер задачи, затем выбрать исполнителя. Не создавать взаимопроверки и дополнительные круги работы только потому, что доступны несколько моделей.

Если одинаково качественный результат можно получить без расхода Claude/Codex — выбирать более дешёвый или бесплатный путь.
