# Drawer — текущее состояние

Актуально на 8 сентября 2026.

## Сейчас

- `master` — текущая наиболее стабильная рабочая версия после ручной проверки и последней сборки. Это **не эталон**: известные и неизвестные баги остаются.
- Поведение продукта определяется `docs/PRODUCT_SPEC.md` и явными решениями владельца.
- Ночная волна больших рефакторингов привела к регрессиям multi-monitor, кромок, геометрии и поведения окон. Не возвращать её целиком и не считать старые зелёные тесты доказательством корректности.
- Muse сейчас отключён владельцем. Antigravity/OpenCode используются только когда для них есть понятная задача.

## Известная сложная проблема

При двух соседних мониторах окно с краем, направленным в сторону соседнего экрана, нельзя просто физически сдвигать за границу: анимация становится видна на соседнем мониторе. Если не сдвигать — анимация пропадает. Желаемое поведение и ограничения описаны в `PRODUCT_SPEC.md`.

## Что уже решено владельцем

- `monitor=cursor` остаётся динамическим: окно и кромка следуют за монитором курсора.
- Можно явно закрепить слот за конкретным монитором.
- Показ слота через хоткей, кромку, Alt+Tab и панель задач должен приводить к одному пользовательскому действию Show.
- Показанное окно становится активным рабочим окном.
- «Убирать окно, когда фокус ушёл» остаётся пользовательской настройкой; при выключении пользователь скрывает окно вручную.
- Кромка должна быть доступна поверх развёрнутых окон; ПКМ открывает меню управления слотом.
- Сброс слота удаляет приложение и возвращает настройки слота к значениям по умолчанию.
- Технические `blur interval`, `focusHotkey`, `activateOnShow`, `animMs/animSteps` не нужны в обычном UI.

## Ближайший порядок работы

1. Довести `PRODUCT_SPEC.md`, включая изображения.
2. Перезапустить архитектора в чистом сеансе с коротким контекстом и долговременной памятью.
3. Перед новой крупной разработкой сверить `AGENT_BOARD.md`: в нём остались исторические формулировки про старый baseline, которые нельзя воспринимать как актуальный продуктовый контракт.
4. Дальше исправлять/развивать программу небольшими проверяемыми кусками, с ручной проверкой там, где важны реальные окна, фокус, анимация и несколько мониторов.
