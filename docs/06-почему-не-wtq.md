# Почему не WTQ

WTQ (`flyingpie/windows-terminal-quake`) — единственный зрелый проект в
этой нише, 780+ звёзд, активная разработка. Он был установлен, настроен
и отлажен в течение дня. Не заработал. Ниже отказы с доказательствами
из журналов — чтобы не возвращаться к нему по кругу.

## О1. Падение на свёрнутом окне

```
Attempted to set window size to something under 200x200, which can mess up windows.
Process exit
```

WTQ запоминает размер захваченного окна. У свёрнутого окна размер
`160×28`, и при попытке его применить программа бросает исключение и
завершает процесс целиком.

## О2. Зависание на служебном окне PhpStorm

```
[Win32WtqWindow|ProcessName:phpstorm64] Could not get window state for window ...
[Wtq.WtqApp|PhpStorm] Attempted to close inactive app ...
```

Правило по классу окна `SunAwtFrame` цепляло служебное окно PhpStorm с
пустым заголовком. WTQ бился об него раз в секунду и зависал, не дойдя
ни до привязки приложений, ни до запуска своего HTTP-интерфейса.
Процесс при этом оставался живым, а окно настроек — пустым.

## О3. Зависший экземпляр блокировал все запуски

```
Found other WTQ process (PID:22700)
WTQ seems to already be running. Running multiple instances can cause
some really weird behavior, so I'm stopping this instance.
Process exit
```

Главный отказ. Обнаружив чужой процесс, новый экземпляр завершался.
Один зависший процесс делал программу неработоспособной, и три запуска
подряд — в 09:06:47, 09:07:49 и 09:08:12 — были убиты этой защитой
молча, без единого сообщения пользователю.

## О4. Окна оставались за пределами экрана

После аварийного завершения WTQ окна приходилось возвращать вручную
через WinAPI. Один раз так «потерялось» окно Chrome, один раз — Блокнот.

## О5. Настройки в графическом интерфейсе не сохранялись

Приложения, добавленные через окно настроек, в файле не появлялись.

## О6. Режим `Manual` непригоден

Попытка сделать несколько слотов для захвата произвольных окон привела
к тому, что все четыре слота вцепились в одно и то же активное окно и
начали ежесекундно перетаскивать его друг у друга за пределы экрана.

## Вывод

Каждый из отказов по отдельности обходится. Вместе они означают, что
программа требует постоянного присмотра, а её собственная архитектура —
служба, HTTP-интерфейс, фоновые задачи, редактор настроек — создаёт
поверхность для отказов, несоразмерную задаче «двигать окно по хоткею».

Все шесть отказов вошли в чек-лист приёмки собственной программы.
